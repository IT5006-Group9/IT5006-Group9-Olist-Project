## 本问题的关键细化

### 业务目的与成功标准

主要使用者为**客户服务/订单运营经理**：下单后以模型估计完整配送时长，辅助到货预期沟通；履约规划可作为次要用途。当前点预测不等于有覆盖率保证的到货区间，模型表现也不能直接证明降低成本或提升满意度。

成功判断使用同一评价订单：与承诺规则、训练均值/中位数、线性及单树 baseline 比较 MAE，并结合 RMSE、R²、偏差、时间折波动与长尾误差。不能预设某个固定提升百分比，也不能把 Phase 1 全历史 MAE 12.73 天作为未来测试通用阈值。

### 文献与特征的连接

Phase 1 p2 提到了配送时长论文中的地理、时间、商家和支付信息；p3 的特征讨论还包含实际配送和处理时长。前者仅是报告摘要，正式建立论文映射时须回到论文核对模型及字段；后者若发生在下单之后，不能直接用于本问题的下单预测。文献中有效的特征不能不经时点检查便迁移到 Olist。

原始表/公式层面的拟研究方向包括：订单预计送达与购买时间的差、客户/卖家邮编地理代理、全部卖家同州/跨州关系、明细金额和运费汇总、商品属性、购买日历信息。每项在实际准备数据时确认列名、缺失覆盖、聚合方法和可用性。

连续配送时长的长尾与分类类别不平衡不同。不因为教师对全组提到 class imbalance，就在回归中直接使用分类过采样。有效长尾保留，变换或稳健损失通过开发期实验决定，并回到天数评价。

## 实施与验收约定

1. 先落实数据/字段、划分与指标，随后训练；来源与未验证假设始终分开。
2. 用 CV/验证期选择特征、参数和复杂模型；对时间变化与极慢订单的解释必须有证据。
3. 测试期锁定，基模型和 stacking 的设计都固定后再共同做最终评价；基础交接先给开发期结果和 OOF，避免测试分数影响后续集成选择。
4. 报告只写实际运行结果；配图、表格、标题、引用与样本数统一；保留 AI 使用说明。
