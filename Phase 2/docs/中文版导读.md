## 问题和数据

我们要在一笔订单刚下单时，预测从购买到客户收货总共需要多少天。输出是连续天数，不是“是否迟到”，也不是“迟到多少天”。

沿用 Phase 1 的 96,470 笔有效已送达订单，306 笔超过60天的真实订单全部保留。输入包括承诺天数、卖家—客户距离、州与路线关系、金额/运费、商品和卖家数量、商品属性、购买日历信息。收货日期用于计算答案和判断历史训练标签是否已经出现，不能拿它预测；评价时也不能把订单最终状态、评论或支付后的信息混入输入。

“从头做”是新建训练工程，不是更换问题或原始数据。新工程直接读取课程表，核对 Phase 1 定义和共享聚合；这样保证不同阶段讨论的是同一个目标，又不用把含结果字段的旧表整张塞进模型。

## 怎样分数据，为什么还没有最终测试分数

- 训练：53,644笔在2018年3月1日前已经购买且收货的订单。
- 验证：2018年3月的7,003笔订单，包含37笔超过60天；等待到7月截止，使这些真实长订单的答案也已出现。
- 另有3,673笔早期订单在训练截止时仍未收货，它们被单独计数，没有被当脏数据永久删除。
- 4–6月保留为标签成熟间隔；7–8月12,507笔作为锁定测试，待基础方案和 stacking 都确定后统一评价。

训练内部三个时间折也只使用预测起点前已收货的历史订单。CV验证样本还受3月截止标签可见性限制，尤其最新折会缺少很慢的订单，因此CV均值不能直接当最终真实未来误差。独立3月验证保留全部已知37笔长尾，是另一层开发期检查。

## 当前结论

以下是**相同7,003笔3月验证订单**上的结果；MAE可以理解为平均差多少天，越小越好。

| 方法 | MAE | RMSE | 主要含义 |
|---|---:|---:|---|
| 直接用承诺时长 | 9.83天 | 12.20天 | 是现成的比较参照 |
| 训练均值 | 8.41天 | 11.94天 | 无需订单特征的常数预测 |
| 训练中位数 | 8.64天 | 12.59天 | 无需订单特征的另一参照 |
| 普通线性回归 | 6.92天 | 10.67天 | 简单 baseline 已有收益 |
| Ridge | 6.91天 | 10.66天 | 3月略低，但更有意义的是压低早期折波动 |
| 单棵决策树 | 7.20天 | 11.11天 | 树家族的 baseline |
| 随机森林 | 7.01天 | 10.83天 | 比单树好，但3月没有胜过线性模型 |

Ridge 是给线性系数加惩罚，减少稀少类别产生过大的影响。普通线性的历史CV平均MAE为9.58天，折间标准差7.09天；Ridge降到4.62天、0.96天。3月二者只差约0.004天，不能宣称有显著或实际的大幅提升。

森林的历史CV均值约4.55天；log1p版本约4.61天，因此没有选择对数目标版本。CV和3月评价的时期、样本及标签成熟条件不同，不能把4.55天和3月6.91天简单排在一起比较。

问题**值得继续做**：学习模型在这个验证期比承诺和常数参照的总体误差低，地理/承诺信息也有预测用途。但当前还不能说它预测得很准或可以直接部署：各学习模型平均低估约4.3天，37笔>60天订单的MAE仍约53天；反而保守的承诺在这些极慢订单上更接近实际。历史训练平均时长12.92天，3月为16.30天，存在明显时期变化，但不能凭数据直接归因于某个物流原因。

森林最依赖距离、承诺、路线关系和客户州。打乱这些信息后误差上升，说明它们在这个模型中有预测作用；这并不证明因果，也不表示单独使用这些列一定准确。

## stacking 接下来接什么

OOF 的意思是：这笔训练订单的预测由**未拿它训练、且只看到更早已完成订单**的模型产生。组合模型用这种预测学习如何组合各基模型，不能拿模型对自己训练数据的拟合值替代。最早14,199笔没有更早历史预测，统一不进入组合训练。

[交接说明](stacking_handoff.md)包含数据、4列OOF、拟合文件和使用顺序。stacking 仍作为独立步骤；最终固定方案后要统一重新拟合可见历史数据并评价锁定测试，不能用测试分数反复修改模型。目前没有上传到 GitHub 或 Google Docs。
