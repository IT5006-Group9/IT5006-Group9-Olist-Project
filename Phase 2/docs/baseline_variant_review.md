# Baseline 与变体复核

更新：2026-10-05。对应主 Notebook cells **8–9**；[本轮已运行实验](../notebooks/baseline_variant_review.ipynb)是独立的模型审查，不替换首轮交接。模型拟合使用已审查的地理 v2，同一16字段、同一训练折和7,003笔三月订单。没有改变目标、筛选或划分，没有拟合 stacking 或评价最终测试。

## 判断与实际改进

**原方案能运行，输入时点与折内预处理正确，但变体的提升不足。** 强化正则化和近期权重后，两条路线都有小幅改善；目前仍不足以支持准确的到货日承诺。不能把原 Ridge 相对线性约六分钟的 MAE 改善，写成显著业务收益。

| 直接使用承诺时长 | 9.825 | 12.202 | +5.732 | — |
| 普通线性 baseline | 6.918 | 10.674 | −4.329 | 39.77% |
| 原 Ridge，alpha 100 | 6.913 | 10.663 | −4.314 | 39.63% |
| **Ridge：7项输入 log1p，alpha 1,000** | **6.847** | **10.584** | **−4.193** | **39.64%** |

| **森林：近期订单180天半衰期权重** | **6.913** | **10.682** | **−4.207** | **40.33%** |

来源：`versions/baseline_review_v2/outputs/tables/model_comparison.csv`。Ridge 相对本轮原 Ridge 的 MAE 降低 **0.95%**；近期森林相对本轮原森林降低 **1.39%**。二者平均误差都仍大于6天，±3天覆盖几乎未变，不能说已经满足业务使用需求。Boosting 在同一树家族内作为诊断；其参数通过训练 CV 选，不据三月结果继续搜寻，不自动增加为正式交接模型。

## 每条路线的问题及含义

1. **普通线性 → Ridge：稳定性改善，表达能力仍有限。** 首个历史折的普通线性 MAE 17.66天，稀少月份系数不稳定；原 Ridge 三折平均 CV MAE 4.616天。扩大 alpha 比较，并对距离、金额、运费、运费比、商品数、卖家数、重量做固定 log1p 后，选中的 Ridge CV MAE 4.540天。变换在填补之后、标准化之前；不变换承诺时长、目标或缺失标记。它缓解尺度/极端输入和系数波动，没有直接学会复杂地理与时间关系。
2. **单树 → 森林：确实改善单树，但不保证优于线性。** 原森林只比较两个深度/叶子组合，搜索很有限。补充全深度、小叶子后，leaf 1 的平均训练 MAE 1.99天，CV MAE却升至5.071天，比原森林4.552天更差。leaf 3 的CV MAE4.602天也未胜出。继续增加容量会把训练订单拟合得更好，但泛化收益没有证据。
3. **近期权重：针对时期差异的小改进。** 权重为 `2 ** (−订单距训练截止的天数 / 180)`，再归一到均值1；每个时间折只使用该折截止前的购买日期。它没有新增未来信息，也没有按三月误差拟合补偿。选中森林CV MAE4.545天，三月6.913天。差异仍小，不能视为已解决时间变化。
4. **训练目标和评价指标不同，值得检查，但没有万能损失。** 原线性/Ridge/树/森林主要拟合平方误差，最终按MAE比较；这合法，并非代码错误。匹配参数的boosting平方损失和绝对损失CV MAE分别4.576和4.641天，CV选择前者。原森林log目标版本CV4.604天也未胜出。不能直接认定log或稳健损失必然更好。

实现及参数来源：[Ridge](https://scikit-learn.org/1.7/modules/generated/sklearn.linear_model.Ridge.html)、[RandomForestRegressor](https://scikit-learn.org/1.7/modules/generated/sklearn.ensemble.RandomForestRegressor.html)、[HistGradientBoostingRegressor](https://scikit-learn.org/1.7/modules/generated/sklearn.ensemble.HistGradientBoostingRegressor.html)官方1.7.2文档。原和新增18组配置在拟合前固定，见[实验代码](../src/baseline_variant_review.py)和`versions/baseline_review_v2/outputs/experiment_protocol.json`。

## 大误差为什么还存在

- 训练订单平均实际时长 **12.92天**，三月 **16.30天**；模型平均低估约4.2天，证明当前输入和拟合没有充分跟上验证时期。现有数据不能据此判定具体原因，更不能直接补加4.2天后宣称泛化改善。
- 三月 **844笔超过30天订单（12.05%）**，占改进 Ridge 绝对误差总和 **42.25%**；其中807笔30–60天订单MAE **22.67天**，37笔>60天MAE **53.02天**。主要问题包括较慢的普通订单，并非只有几笔离群值。
- 训练CV最新折受“3月前标签可见”约束，**没有>60天订单**。约4.5天CV与约6.8天三月结果不能当作同一分布的准确率。数据审计确认订单与字段有效，不等于CV能无偏代表未来。当前划分保持；需要另定义历史成熟标签回测来检查排名的稳健性。

## 后续改进的优先级

1. 保留线性与单树 baseline，暂以本轮 Ridge/近期森林作为候选版本；停止仅靠加深树、加树数或扩大无目的参数网格。
2. 做有针对性的**输入表达**试验：购买时日历/节假期代理、承诺与距离的交互、区域路线关系。若加入历史配送统计，只能使用预测时已收货的更早订单，在每个时间折重新计算；未知组合须有训练期回退规则。以上是下一轮假设，尚未实现或证明有效。
3. 增加明确的历史成熟标签敏感性回测，保留当前三月验证和最终测试边界；报告区分条件化CV和未来时期误差，不通过删除慢订单或换测试月份美化成绩。
4. 方案冻结后统一更新正式 Notebook、pipeline、OOF和交接。Stacking不能靠组合几个都低估的模型自动补回遗漏的时期信息。最终测试只在基模型和stacking设计冻结后评价。
